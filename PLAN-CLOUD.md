## 4. Règles de travail transverses (valent pour toutes les étapes)

1. **docs/ en lecture seule.** Aucune modification. Les contradictions sont consignées, pas tranchées.
2. **Écarts et choix provisoires → `A-TRANCHER.md`** à la racine du dépôt (nouveau fichier, hors docs/), une section par étape : pour chaque écart, la source (maquette / cahier / plan), le choix **provisoire** fait dans le code pour que l'écran marche, et la question posée à Nohé. Repris dans la description de la PR. C'est le mécanisme qui permet d'avancer sans « trancher seul » : tout choix non couvert par les documents y est écrit.
3. **Jamais de fausses données.** Tout ce qui vient d'un adaptateur simulé est marqué « simulé » à l'écran (pastille sur la donnée, bandeau sur l'écran). Les coûts simulés portent `simule=1` en base et n'alimentent pas la jauge « réelle » après bascule. Les PNG/GLB simulés sont des aplats/boîtes (honnêtes), jamais des images « réalistes » inventées.
4. **Une seule PR**, ouverte après l'étape 1, titre mis à jour (« Étapes 1 à N »), description = checklist par étape + lien `A-TRANCHER.md` + ce que Nohé doit voir. Push après chaque étape. Si Nohé fusionne en cours de route : `git fetch origin main && git checkout -B claude/atelier-3d-status-xp09v0 origin/main`, puis continuer (règle de la PR fusionnée).
5. **Commits** : par sous-étape ou correctif, message en français, corps court, trailers `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` et `Claude-Session: https://claude.ai/code/session_01KQLXJmDp3MHRuYJy2evytb`. Les imports depuis l'archive portent `Repris-de: origin/claude/sleepy-mendel-tc8e34 @ 18d6c5f`. Pas d'identifiant de modèle dans le code ni les commits.
6. **Fini = tests verts + utilisable depuis l'écran.** Par étape : `pytest -q`, `ruff check`, `npm --prefix web test`, `npm --prefix web run lint`, `npm --prefix web run build` (tsc + vite), puis `npm --prefix web run test:e2e` (Playwright contre `python dev.py` réel avec `ATELIER_*` dans un dossier temporaire). On corrige le code, jamais le seuil ; aucun test `skip` sauf ceux marqués `blender`.
7. **Contrat interface/API** : `web/src/test/contrat.json` généré par `python -m tests.api.contrat_web --ecrire` depuis la vraie API ; test gardien `test_contrat_web_a_jour` ; `api-mock.ts` ne contient aucune constante écrite à la main. À régénérer à chaque route ajoutée.
8. **Fichiers servis** sous `/api/fichiers/...` uniquement (rendus, GLB d'aperçu, planches, zips), avec contrôle anti-traversée ; `vite.config.ts` `build.assetsDir = "statique"` pour libérer `/assets/:id` (route React Fiche asset).
9. **Migrations** : `api/migrations/NNN_nom.sql`, plages d'ARCHITECTURE.md : 000-009 socle, 010-019 styles, 020-029 lots/brief, 030-039 file/coûts, 070-079 revue, 080-089 bibliothèque, 090-099 publication, 100-109 générateurs/accueil. Chaque migration indépendante (`CREATE TABLE IF NOT EXISTS`, un seul `ALTER TABLE` par colonne, jamais deux migrations qui ajoutent la même colonne) pour que 040-069 (étapes 5-7, plus tard) s'insèrent sans conflit.
10. **Tâches** : tout ce qui dure > 1 s passe par la file (`creer_tache`) ; une erreur **définitive** (`TacheDefinitive` : Blender introuvable, clé absente, plafond atteint, handler d'une étape non construite) passe directement en `echouee` sans relance, avec événement + notification honnête. 12. **Accessibilité** : vrais `button/a/label`, 44 px, `:focus-visible`, `Fenetre.tsx` (Échap + retour du focus) pour toute fenêtre.
13. **Pas de nom de thème/objet/lot en dur dans `web/src`** (test anti-« Rome ») ; couleurs via `tokens.css` (test : toutes dans docs/maquette) ; budgets/matériaux via style.yaml.
